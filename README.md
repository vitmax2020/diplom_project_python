Задание:
Кейс 9: Валидатор email-адресов с использованием регулярных выражений

Цель: Разработать программу на Python для проверки корректности электронных адресов с помощью регулярных выражений. Программа должна принимать как одиночные адреса, так и список адресов из файла, выводить детальный результат проверки и сохранять историю операций. Использовать ИИ-инструмент для генерации регулярного выражения и обработки ошибок.

Задачи:

1. Реализовать функцию проверки одного email-aдpeca на соответствие стандартному формату (например, username@domain.zone).
Использовать регулярное выражение, которое учитывает:
  . допустимые символы в локальной части (буквы, цифры, точки, дефисы, подчёркивания);
  . обязательное наличие символа @;
  . корректное доменное имя (буквы, цифры, дефисы, точки);
  . наличие как минимум одной точки в доменной части, окончание из 2-6 букв.

2. Добавить возможность пакетной проверки:
  . чтение списка email-адресов из текстового файла (по одному на строку);
  . проверка каждого адреса;
  . сохранение результатов в выходной файл с пометками «корректен» / «некорректен» и указанием причины ошибки.

3. Создать консольный интерфейс с меню, позволяющий:
  . ввести один адрес для проверки вручную;
  . указать путь к файлу со списком адресов для пакетной проверки;
  . просмотреть историю последних проверок (в памяти или из лог-файла);
  . выйти из программы.

4. Реализовать сохранение истории проверок в JSON-файл history.json.
Каждая запись должна содержать: время проверки, проверенный адрес, результат (корректен/некорректен), причину ошибки (если есть).

5. Использовать ИИ-инструмент (например, ChatGPT, Cursor Al, GitHub Copilot) для:
. генерации эталонного регулярного выражения для проверки email (с комментариями);
. создания кода для разбора причин ошибки (например, отсутствие @, недопустимые символы, неправильный домен);
‚ обработки исключений при работе с файлами (отсутствие файла, кодировка).

6. Реализовать валидацию ввода пользователя (пустая строка, некорректный путь к файлу) с понятными сообщениями об ошибках.

7. (Опционально) Добавить:
. поддержку «сырых» регулярных выражений, вводимых пользователем для кастомной проверки;
. графический интерфейс на tkinter;
. проверку существования домена через DNS-sanpoc (He обязательно, но усложняет задачу).

Критерии оценки:
. Корректность работы регулярного выражения (тесты с заведомо правильными и неправильными адресами).
. Полнота и понятность отчёта о проверке (почему адрес признан некорректным).
. Надёжность пакетной обработки и сохранения результатов.
. Качество обработки ошибок (файл не найден, пустой файл, неверный формат).
. Документированное использование ИИ (текст запросов, скриншоты диалога, примеры сгенерированного кода).
. Читаемость кода и соблюдение PEP 8.
. Наличие Git-репозитория с минимум 3 осмысленными коммитами.
